# 바닥 점검 — **읽고, 말하고, 안 고친다**

이미 있는 저장소가 **서버 바닥**(벽 · 시크릿 탐지 · 의존성 봇 · SAST · Actions 정책)을
갖췄는지 본다. **brownfield 진입로**다.

🔴 **`/new-project` 와 헷갈리지 마라.** 그건 **저장소를 만들고 실패하면 지운다**(fail-closed).
이 커맨드는 **아무것도 만들지 않고 아무것도 고치지 않는다.**

## 돌리는 법

```bash
python3 ~/standards/tools/repo_audit.py --repo <owner/name>
```

`owner/` 를 빼면 `coolbress` 로 친다. 인자를 다 빼면 **우리 네 저장소**를 본다.

⚠️ **읽기 권한이 필요하다** — `GH_TOKEN` 에 Administration·Code scanning **읽기**가 있어야
룰셋과 CodeQL 이 보인다. 없으면 그 항목이 `⚪ unknown` 으로 나온다.
🔵 **`unknown` 은 실패가 아니다** — *"감사기가 눈을 뜨는 것과 벽이 무너지는 것은 다른 문장이다."*

## 무엇이 나오나

```
🔴 문제  |  🟡 못 봄  |  ✅ 통과
METRIC audited=1 findings=N unknown=M
⚪ 우리 묶음 전용 검사(라벨·문서 묶음)는 건너뛴다 — 남의 거버넌스가 아니다
```

🔴 **마지막 줄이 중요하다.** 남의 저장소에는 **기본 기대값**만 건다.
우리 거버넌스(회부 라벨 · `AGENTS.md` 규약)를 요구하면 그건 **감사가 아니라 참견**이고,
그 저장소는 **영원히 빨간불**이 되어 감사기가 무시당한다.

## 결과를 사용자에게 어떻게 말하나

1. **찾은 것을 그대로** 옮긴다. 없는 것을 있다고 하지 않는다
2. 🔴 **고치지 않는다.** 대부분이 **관리자 권한**을 요구한다(룰셋 · Actions 정책 · CodeQL · 시크릿) —
   에이전트에게는 그 권한이 **없다.** 명령을 만들어 **사람에게 넘긴다**
3. **순서를 말한다** — 벽(룰셋)보다 **검사가 먼저 보고돼야** 한다.
   순서를 뒤집으면 요구한 검사가 영원히 안 와서 **머지 불가 저장소**가 된다
4. ⚠️ **바닥은 가장 약한 항목으로 점수가 매겨진다.** 아홉이 초록이고 하나가 빨강이면 **빨강이다**

## 🔴 못 보는 것

**서버 설정만 본다.** 코드 품질·테스트 유무·문서 내용은 **여기서 안 본다** —
그건 `ci / test` 와 리뷰(`/review`)의 일이다. 이 커맨드가 초록이라고 **프로젝트가 좋은 게 아니다.**
