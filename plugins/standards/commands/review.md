# diff 리뷰 — **제3자에게 맡긴다**

설정된 리뷰어: **`${user_config.reviewer}`**
(바꾸려면 `/plugin` 에서 `coolbress-standards` 설정 · 또는 `claude plugin install … --config reviewer=<값>`)

## 왜 외부 모델을 먼저 쓰나

🔴 **같은 세션의 같은 모델이 자기가 쓴 diff 를 보는 것은 *제3자* 가 아니다.**
근거는 통제실험이 보인 **컨텍스트 분리**의 효과다(`standards` 코퍼스 `IPW-006`).
외부 모델은 그 분리가 **구조적으로 보장**된다 — 우리 쪽 대화도, 의도도, 변명도 안 들고 간다.

## 무엇을 할지

### `codex` — 권장

```
/codex:review                 diff 를 리뷰한다
/codex:adversarial-review     구현 접근과 설계 선택에 시비를 건다
```

두 번째는 **설계가 흔들릴 만한 PR** 에 쓴다. 첫 번째는 기본이다.

### 그 밖의 외부 모델

리뷰어 이름이 `codex` 가 아니면 **그 도구의 리뷰 명령을 쓴다.**
없으면 **diff 를 그 모델에 붙여넣고** 아래 두 축으로 묻는다:

1. **Standards** — 이 저장소가 **문서로 적어둔 규약**을 따르나 (`AGENTS.md` · `CONTRIBUTING.md`)
2. **Spec** — 이슈의 **인수기준(`AC-n`)** 을 실제로 만족하나

### `none` — 외부 모델이 없을 때만

🔶 **Claude Code 내부로 떨어진다.** 그때는 **사용자에게 한 줄로 말한다:**

> *"외부 리뷰어가 설정돼 있지 않아 같은 모델이 봅니다 — **제3자성이 없습니다.**
> 구독 중인 외부 모델이 있으면 `/plugin` 에서 `reviewer` 를 바꾸는 편이 낫습니다."*

그리고 `mattpocock` 의 `code-review`(**2축 · 병렬 서브에이전트**)를 쓴다 — 최소한 **컨텍스트는 갈린다.**

## 🔴 어느 쪽이든 — 리뷰는 **안전망이 아니다**

최선 조건에서도 **F1 28.6%** 다. **오류의 71% 를 놓친다**(`standards` 코퍼스 `IPW-007`).

**판정은 벽이 한다.** `ci / lint`·`typecheck`·`test`·`build`·`secrets`·`diff-size` 가 빨간불이면
리뷰가 뭐라 하든 머지는 안 된다. 리뷰는 **벽이 못 보는 것**(설계 판단·읽히는가)만 본다.
