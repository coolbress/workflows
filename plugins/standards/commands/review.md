# diff 리뷰 — **제3자에게 맡긴다**

설정된 리뷰어: **`${user_config.reviewer}`**
(바꾸려면 `/plugin` → `coolbress-standards`, 또는 `claude plugin install … --config reviewer=<값>`)

## 0. 리뷰어를 정한다

| 설정값 | 할 일 |
|---|---|
| **`auto`**(기본) | `claude plugin list` 로 **설치된 것을 본다.** `codex` 가 있으면 그것. 없으면 `none` 처럼 처리 |
| `codex` | 아래 §1 |
| 그 밖의 이름 | 그 도구의 리뷰 명령. 없으면 §2 |
| `none` | §3 |

🔴 **설정된 리뷰어가 설치돼 있지 않으면 조용히 넘어가지 말고 한 줄로 말한다** —
*"`<이름>` 이 설치돼 있지 않아 내부로 처리합니다."*

## 1. `codex` — 권장

```
/codex:review                 diff 를 리뷰한다
/codex:adversarial-review     구현 접근과 설계 선택에 시비를 건다
```

두 번째는 **설계가 흔들릴 만한 PR** 에만. 첫 번째가 기본이다.

## 2. 그 밖의 외부 모델

diff 를 그 모델에 주고 **두 축**으로 묻는다:

1. **Standards** — 이 저장소가 **문서로 적어둔 규약**을 따르나 (`AGENTS.md` · `CONTRIBUTING.md`)
2. **Spec** — 이슈의 **인수기준(`AC-n`)** 을 실제로 만족하나

## 3. `none` — 외부 모델이 없을 때만

🔶 내부로 떨어진다. **그때는 사용자에게 반드시 말한다:**

> *"외부 리뷰어가 없어 **같은 모델이 봅니다 — 제3자성이 없습니다.**
> 구독 중인 외부 모델이 있으면 `/plugin` 에서 `reviewer` 를 바꾸는 편이 낫습니다."*

그리고 `mattpocock` 의 `code-review`(**2축 · 병렬 서브에이전트**)를 쓴다 — 최소한 **컨텍스트는 갈린다.**

---

## 🔴 사다리는 셋이고, **기본은 가장 낮은 칸이다**

| 칸 | 무엇 | 언제 |
|---|---|---|
| **1 · 수동**(이 커맨드) | 내가 부를 때만 돈다 | **기본.** 비용이 예측 가능하다 |
| 2 · **Stop 게이트** | 턴이 끝나는 것을 막고 리뷰가 통과해야 놓아준다 | 🔶 **옵트인** — `codex` 플러그인의 `--enable-review-gate` |
| **3 · 벽**(CI) | 푸시마다 돈다. 빨간불이면 **머지가 안 된다** | 🔒 **유일한 진짜 집행** |

🔴 **2칸을 기본으로 켜지 않는다.** 실사용 보고가 일관된다 —
***"수동 리뷰부터 시작하라"*** · ***"게이트는 비용 폭주를 만들 수 있다"***:
**Claude 가 지적을 고치면 그 수정이 다시 리뷰를 부르고, 그것이 또 수정을 부른다.**
OpenAI 문서 자신이 *"사용량을 빠르게 소진할 수 있으니 **직접 감독할 때만** 켜라"* 고 적는다.

🔵 **그리고 이것이 구조적 차이다** — **되먹임 루프는 에이전트 *안쪽* 게이트에만 생긴다.**
벽은 **푸시마다 한 번** 돌기 때문에 같은 루프를 만들 수 없다.

## 🔴 어느 칸이든 — 리뷰는 **안전망이 아니다**

최선 조건에서도 **F1 28.6%**, **오류의 71% 를 놓친다**(`standards` 코퍼스 `IPW-007`).

**판정은 벽이 한다.** `ci / lint`·`typecheck`·`test`·`build`·`secrets`·`diff-size` 가 빨간불이면
리뷰가 뭐라 하든 머지는 안 된다. 리뷰는 **벽이 못 보는 것**(설계 판단·읽히는가)만 본다.
